# 자원봉사 실적 집계 · 보고서 자동화

`2026년 자원봉사활동관리` 스프레드시트의 **활동일지**를 기준으로
"몇 명이 몇 시간 활동했는가"를 주 / 월 / 연 / 임의 기간 단위로 **실시간** 집계하고,
월간·연간 실적보고서를 버튼 한 번으로 만드는 Google Apps Script입니다.

> 왜 Apps Script인가: 활동일지는 이미 Apps Script 웹앱(서명 입력 폼)이 쓰고 있는 시트입니다.
> 같은 스프레드시트 안에 **수식 기반 집계 시트**를 두면 별도 서버·DB 없이 활동일지가 바뀌는 즉시 숫자가 바뀝니다.
> 소유자(communitycenter.or.kr) 계정에서 한 번 실행하면 끝입니다.

---

## 1. 설치 (5분, 스프레드시트 소유자 또는 편집 권한 계정)

1. 스프레드시트 열기 → **확장 프로그램 → Apps Script**
2. 왼쪽 `파일` 옆 **+ → 스크립트** → 이름 `실적보고` → [`Code.gs`](Code.gs) 내용 전체 붙여넣기 → 저장(⌘/Ctrl+S)
   - 기존 프로젝트에 이미 `onOpen()`이 있으면, 붙여넣은 파일의 `onOpen`을 `onOpen_report`로 바꾸고
     기존 `onOpen()` 안에 `addReportMenu();` 한 줄을 추가하세요.
3. 스프레드시트 탭 **새로고침** → 상단 메뉴에 **📊 실적보고** 가 생김
4. **📊 실적보고 → 집계 시트 설치 / 재생성** → 권한 승인(최초 1회) → 완료

생성되는 시트 7개:

| 시트 | 용도 | 조작 |
|---|---|---|
| **실적대시보드** | ① B5·B6에 기간 입력 → 건수·실인원·시간·프로그램별 표 ② 이번 주/지난 주/이번 달/지난 달/올해/작년/전체 자동 표시 | 날짜 2칸만 입력 |
| **월별실적** | 1~12월 건수·실인원·시간, 정기/단기 분리, 프로그램×월 피벗 2개, 차트 2개 | B2 연도 |
| **주별실적** | 월~일 기준 53주, 이번 주 자동 강조 | B2 연도 |
| **프로그램별실적** | 봉사활동처 기준 프로그램별 건수·실인원·시간·첫/최근 활동 | B2 연도 (0 = 전체) |
| **봉사자별실적** | 봉사자별 건수·시간·참여 프로그램 (총 시간 순) — 우수봉사자 선정, VMS 대조용 | B2 연도 (0 = 전체) |
| **데이터점검** | 종료≤시작, 활동일 누락, 명단에 없는 이름, 활동처 미등록 프로그램, VMS 미등록 | 활동일지에서 수정하면 자동 소멸 |
| `_calc` (숨김) | 위 시트들이 참조하는 정규화 테이블 (활동일지 → 시간·연·월·주·상태) | 건드리지 않음 |

## 2. 보고서 만들기

메뉴 **📊 실적보고** →

- **이번 달 / 지난 달 보고서 만들기** — 클릭 1회
- **월간 보고서 (연·월 입력)** — `2026-10`
- **연간 보고서 (연도 입력)** — `2026`
- **기간 보고서 (시작~종료 입력)** — `2026-07-01~2026-09-30`

→ `보고서_20261001-20261031` 같은 시트가 생기고(값 고정, 수식 없음),
`CFG.REPORT_FOLDER_ID` 폴더 아래 **실적보고서/** 에 PDF가 저장됩니다.
보고서 구성: 핵심지표 → 구분별(정기/단기) → 월별(2개월 이상일 때) → 프로그램별(담당자 포함) → 봉사자별 → 확인 필요 행.

## 3. 집계 규칙 (보고서에 그대로 명시해도 되는 정의)

| 항목 | 정의 |
|---|---|
| 활동 건수 | 활동일지 1행 = 1건 (봉사자 1명 × 활동 1회) |
| 활동시간 | `종료 − 시작` (시간, 소수 둘째 자리). **종료 ≤ 시작이거나 비어 있으면 0**으로 계산하고 데이터점검에 표시 |
| 실인원 | 기간 안에서 `봉사자명(이름+생년월일)` 중복 제거. **월별 실인원의 합 ≠ 연간 실인원** |
| 1인 평균 | 총 시간 ÷ 실인원 |
| 주 | 월요일 ~ 일요일 (ISO 주차 표기) |
| 프로그램 키 | 활동일지 `활동프로그램` = 봉사활동처 `TypeID` (A열) |

## 4. 설정 (`Code.gs` 상단 `CFG`)

| 키 | 기본값 | 설명 |
|---|---|---|
| `REPORT_FOLDER_ID` | 자원봉사 드라이브 폴더 | PDF 저장 위치. 빈 문자열이면 PDF 생략 |
| `REPORT_SUBFOLDER` | `실적보고서` | 위 폴더 안에 자동 생성되는 하위 폴더 |
| `ORG_NAME` | `''` | 보고서 제목 앞에 붙는 기관명 |
| `COL` | A=LogID … G=활동일, H=시작, I=종료, P=VMS | 활동일지 열 순서를 바꾸면 여기만 수정 |

## 5. 다른 시스템에서 숫자만 받아가기

기존 웹앱 `doGet(e)` 안에 한 줄:

```js
if (e.parameter.report) return reportApi(e);
```

```
…/exec?report=1&from=2026-10-01&to=2026-10-31
→ {"count":68,"people":44,"hours":170,"byProgram":[…],"byKind":{…},"byMonth":[…],"invalid":[…]}
```

개인정보 최소화를 위해 외부 응답에는 봉사자 이름 목록을 넣지 않습니다.
스크립트 내부에서는 `getSummary(startDate, endDate)`를 직접 호출하면 전체 객체를 받습니다.

## 6. 검증 메모

- 2026-11-12 기준 활동일지 700행을 익명화한 사본으로 수식 전체를 검증했고, Python 독립 계산과 월별·주별·프로그램별 수치가 일치했습니다.
- Google Sheets에서 `SUMIFS`는 배열 조건을 펼치지 않아(`COUNTIFS`는 펼침) 합계 열은 모두 `MAP/LAMBDA`로 작성했습니다.
- `QUERY`의 `date '…'` 비교는 참조 열이 **날짜 서식**이어야 동작합니다. `_calc` E·I열 서식을 지우지 마세요.
- 활동일지 행이 늘어나 `_calc`보다 커지면 `#REF`가 날 수 있어, 시트를 열 때(`onOpen`) 자동으로 `_calc` 행 수를 맞춥니다. 수동: 메뉴 → **집계 범위 새로고침**.
